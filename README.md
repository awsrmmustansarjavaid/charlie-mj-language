# Charlie MJ Language --- v2.0.0

> A lightweight, local-first Chrome extension for learning languages
> through YouTube.

![Charlie MJ Language v2.0.0 Stable Beta](assets/charlie-mj-language-main-thumbnail.png)

Charlie MJ Language turns YouTube into a practical language-learning
workspace while keeping the original fast transcript workflow as its
core engine. It adds transcript tools, Dual Transcript, subtitle
controls, vocabulary and sentence learning, automatic subtitle pausing,
audio replay, Favorites, Categories, Learning Groups, YouTube metadata
and thumbnails, Suggestions, and local data synchronization.

## What's new in the latest v2.0.0 build

- Focus Modes, delayed Video Info / Description hiding and Restore-on-end (Settings > Productivity & Focus Intelligence).
- Rule-based, country-first category suggestions with a "Why was this category suggested?" explanation.
- Metadata rules Data Sync: export, import, directory ZIP, restore defaults, compare with GitHub.
- Details: `docs/37-update-2026-10-27-focus-categorization-final.md`.

## Key Features

### 🎬 Transcript & Subtitle Tools
- ⚡ **Quick Fetch Complete Transcript** — Fetch the complete available YouTube caption track with or without timestamps.
- 🌐 **Dual Transcript** — Display original and YouTube-native translated transcripts together.

- 🎯 **Click-to-Seek Transcript** — Click transcript rows to jump to the corresponding video timestamp.

- 📖 **Instant Subtitle Auto-Follow** — Automatically scroll to the active subtitle with responsive synchronization.

## Latest Update --- 2026-10-25

This build is a fixes-and-feature update on top of v2.0.0. It is
additive only: the core transcript engine, Dual Transcript, Word
Learning, Sentence Learning and all existing Library data are untouched.

### Fixed

-   **YT Transcript Pro → Open settings.** The settings icon in the
    transcript window header now opens the extension Settings page
    directly on the **YT Transcript Pro** tab. If a Settings tab is
    already open it is re-used and brought to the front instead of
    opening a duplicate. The page also accepts a deep link such as
    `options.html?category=YT%20Transcript%20Pro`.
-   **My Library search.** Search now reliably returns results across
    videos, History, Word Learning, Sentence Learning, Subtitle
    Learning, Vocabulary, Bookmarks, Watch Later, Captures, Favorites,
    Checkpoints, Transcripts and Notes.
    -   One saved item with an unexpected shape (for example `tags`
        stored as text instead of a list) no longer breaks the whole
        search or render.
    -   Matching is case-, accent- and Turkish-`ı/İ`-insensitive, so
        `nasilsin` finds *Nasılsın*; multi-word queries match when every
        word is present.
    -   Only saved *values* are searched (not internal field names), so
        searching a word such as `type` no longer matches everything.
    -   Typing is debounced, `Enter` searches immediately, large result
        sets are capped at 400 with a notice, and a failing card can no
        longer blank the result list.
    -   Refresh and tab changes keep an active search instead of
        clearing it.

### Fixed: mouse-wheel scrolling in YT Transcript Pro, export bugs, clean code

-   **Mouse wheel in YT Transcript Pro (inside the Transcript window).**
    Two fixes, both tested with the real extension loaded in Chromium:
    1.  *Layout* (`src/content/youtube.css`, section *YT Transcript Pro
        integration*): the list had no height limit, so it could never
        scroll itself and the wheel scrolled the whole panel body (header,
        languages and search scrolled away). The tab now fills the panel
        body and the list is a real scroller (at least 300 px high). In a
        very small window the panel body scrolls so nothing is clipped.
    2.  *Safety net* (`src/transcript-pro/ytp-content.js`, right after
        `proFollower().bind(els.lines)`): if the page swallows the wheel
        event so that neither the list, the panel body nor the page moves,
        the list is scrolled smoothly by the extension itself. When the
        browser scrolls normally this code does nothing.
-   **My Library exports / CSV import.** A stale second copy of the
    export helpers in `src/dashboard/dashboard.js` overrode the correct
    ones and wrote the literal text `\n` instead of line breaks (TXT / CSV
    export, CSV import, download helper). The stale copy was removed and
    the Anki (TSV) and SRT / VTT export lines that had the same escaping
    mistake were corrected.
-   **Caption discovery.** `discoverCaptionTracksFromPlayer()` in
    `src/content/youtube.js` referenced an undefined variable (`root`) and
    always failed silently before reading the player response. Fixed.
-   **Settings page HTML.** Removed two invalid `</input>` end tags in
    `src/options/options.html`.

### Code style

All `.js`, `.css`, `.html` and `.json` source files are formatted with
Prettier (2 spaces, single quotes, semicolons, 100 columns). The rules
are stored in `.prettierrc.json` and `.editorconfig`; `database/`, `data/`
and `assets/` are ignored (`.prettierignore`). To keep the code clean
after your own edits run:

```
npx prettier --write "src/**/*.{js,css,html,json}" "*.json"
```

### Fixed: transcript scroll sync, tab order and Dock / Float

-   **YT Transcript Pro and Dual Transcript now follow the video.** The
    highlighted line always matches the current video subtitle and the
    list scrolls to it whenever the subtitle changes -- while playing,
    and also when you seek (timeline click, arrow keys, clicking a
    transcript line) even if the video is paused.
    -   Scrolling now moves **only the transcript list**; the YouTube
        page itself no longer jumps (the old `scrollIntoView` call moved
        the whole page).
    -   **Manual scrolling works anywhere** (mouse wheel, touch,
        scrollbar drag, keyboard). Following pauses while you browse
        (YT Transcript Pro: *Resume Scroll Delay*, default 4 s; Dual
        Transcript: ~1.8 s) and then catches up to the current subtitle.
        Seeking the video cancels that pause and jumps straight to the
        right line.
    -   A search in YT Transcript Pro is never overridden by auto-scroll,
        and *Auto Scroll* works even when *Highlight Current* is off.
-   **Transcript window tab order** is now: *Transcript, Dual
    Transcript, YT Transcript Pro, Vocabulary, Bookmarks, Watch Later,
    Notes*.
-   **Dock / Float button (YT Transcript Pro header) works inside the
    Transcript window.** *Float* detaches YT Transcript Pro into its own
    draggable, resizable window (position and size are remembered) and
    leaves a "Dock it back here" button in the tab; *Dock* returns it to
    the Transcript window. A floating window stays open when you switch
    to another Transcript-window tab.

### New: Subtitle Learning (My Library)

A new **💬 Subtitle Learning** tab (My Library → Learning) stores
subtitles together with their translation, just like Sentence Learning.

-   **Save from the YT Transcript Pro window:** every transcript line has
    a new bookmark button next to *Copy line*, and selecting several
    lines shows **Save selected (n)**. The original subtitle, its
    translation (when a translation language is on), timestamp, video
    title, channel and link are saved. Duplicates (same video, same text,
    same time) are never created twice; a missing translation is filled
    in on re-save.
-   **Same features as Sentence Learning:** Details / Study Card with
    word-by-word analysis, Copy, Add / Move to Collection, Checkpoint,
    Favorite, *Open at timestamp*, Download, Export (TXT / MD / CSV /
    JSON / Word / PDF), Remove, Import, level / tag / video / type
    filters, and global search.
-   **Setting:** *YT Transcript Pro → Show Line Save* (on by default)
    hides or shows the per-line save button.
-   **Storage key:** `subtitleLearning` (local `chrome.storage.local`).

## Critical Core Functionality

The original transcript system is the primary and authoritative
transcript engine.

The v2.0.0 release does **not** replace or rewrite the
original transcript-fetching implementation.

The default engine remains:

``` text
legacy-youtube
```

The core workflow is:

1.  Open a YouTube video.
2.  The extension detects the video.
3.  The original transcript engine fetches the available complete
    caption track.
4.  The complete timestamped transcript becomes available.
5.  The user can scroll through the transcript.
6.  Transcript rows remain associated with timestamps.
7.  Clicking a transcript row seeks the video to that timestamp.
8.  Playback and transcript position remain synchronized where
    supported.
9.  Existing subtitle, translation, vocabulary, sentence, notes, and
    learning workflows can use the transcript.

### Core preservation requirement

New services must never:

-   replace `legacy-youtube`
-   rewrite its fetching algorithm merely to support another service
-   delay the original transcript while waiting for an optional service
-   create a second YouTube player
-   continuously intercept YouTube traffic for basic transcript
    operation
-   remove transcript scrolling or timeline seeking
-   remove existing transcript-learning functionality

The original transcript remains the reference source for additional
transcript systems.

## Performance and Lightweight Architecture

v2.0.0 Stable Beta is designed so optional services do not make normal
YouTube playback unnecessarily heavy.

### Startup principle

The extension should load only what is required for normal operation:

-   core extension logic
-   existing transcript functionality
-   required settings
-   lightweight UI
-   small indexes/cache metadata

Optional services remain dormant until needed.

### Service lifecycle

Optional services follow an event-driven lifecycle:

``` text
IDLE
  ↓
ACTIVE
  ↓
INACTIVE
  ↓
SLEEPING
  ↓
WAKE
  ↓
ACTIVE
```

Enabled does not mean continuously running.

### Performance controls

Performance settings provide controls for:

-   lightweight startup
-   on-demand service activation
-   service sleep timeout
-   resource-intensive service enable/disable
-   lazy loading
-   caching
-   background-task controls
-   event-driven operation
-   reduced unnecessary polling
-   reduced unnecessary YouTube requests

The goal is for normal YouTube playback and the original transcript path
to remain the priority.

## Transcript Windows Scroll

One shared scroll controller (`src/lib/transcript-scroll.js`) drives all three transcript tabs: **Transcript**, **Dual Transcript** and **YT Transcript Pro**.

-   While the video **plays**, the list follows the current subtitle.
-   While the video is **paused**, the list stays still.
-   **Seeking** (YouTube timeline, clicking a line, replay) always jumps the list to the new subtitle, paused or playing.
-   **Manual scrolling** (wheel, touch, scrollbar, keys) holds following; it resumes after the configured delay while playing, or when you seek, click a line or press Play.
-   Only the transcript scroll container moves. The YouTube page itself is never scrolled.

Configure it in **Settings → Subtitles & Timeline → Transcript Windows Scroll**: master switch, per-tab switches, subtitle position (center/top/bottom), smooth or instant animation, manual-scroll respect, resume delay and jump-on-seek.

## Architecture Principles

### Strict additive-only development rule

Existing working systems and features are treated as **untouchable
unless the user explicitly requests a change**.

When adding functionality:

-   add new code as an independent subsystem where practical
-   do not remove an existing feature to make room for a new feature
-   do not replace a working implementation simply because a new
    implementation is available
-   do not change unrelated existing behavior
-   keep existing settings and storage compatible
-   test the original feature before and after every new integration
-   treat a regression in an existing working feature as a release
    blocker

### Core principles

1.  **Preserve the core** --- the original fast complete-transcript
    engine is not replaced.
2.  **Add, don't remove** --- new functionality is additive.
3.  **Independent services** --- Dual Transcript, Favorites, Categories,
    Data Sync, Suggestions, Intelligence, and other services operate
    independently.
4.  **No unnecessary continuous work** --- optional services should
    sleep when inactive.
5.  **Event-driven operation** --- prefer events and explicit user
    actions over aggressive polling.
6.  **Stable identities** --- use YouTube Channel IDs and Playlist IDs
    instead of names as primary identifiers.
7.  **Safe storage** --- do not silently erase existing user data.
8.  **Backward compatibility** --- existing settings, storage,
    transcript workflows, and learning records should remain usable.
9.  **No second YouTube player** --- additional transcript services must
    not recreate the YouTube player.
10. **Original transcript remains authoritative** --- additional
    transcript sources are compared against the original rather than
    replacing it.

## Troubleshooting: Transcript Panel Looks Transparent or Faded

![Transcript panel faded vs solid](assets/Troubleshooting%20Transcript%20Panel%20Looks%20Transparent%20or%20Faded.png)

**Problem:** The YT Transcript Pro window looks transparent or dimmed on YouTube, even though **Background opacity** is already set to 100%.

**Cause:** Another extension (for example a language-learning overlay with **Focus** or **Theme** modes) is dimming or restyling everything on the page except the video. This is not a YT Transcript Pro setting.

**Fix:**

1. Open **Settings → Appearance → Window → Background opacity** and confirm it is **100%**.
2. In the other extension's toolbar, switch **Focus** and **Theme** to **OFF**.
3. If it is still faded, disable the other extension in `chrome://extensions`, then refresh the YouTube page.
4. Optional: switch YT Transcript Pro to **floating** mode so the window sits above the page.
